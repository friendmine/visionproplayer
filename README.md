# Vision Player

原生 visionOS 播放器：片库、统一播放界面、左右 / 上下 3D、实验性 AI 立体效果与空间影院。底层使用 Apple AVPlayer + 官方 VLCKit 4。

## 打开和运行

1. 先执行 `python3 Scripts/prepare_depth_model.py`，下载、校验并编译 Apple 提供的 Depth Anything V2 Small F16 模型（约 44 MB 下载）；随后用 Xcode 打开 `VisionProPlayer.xcodeproj`，选择 `VisionProPlayer` scheme。
2. 等待 Swift Package 解析官方 VLCKit。初次下载约 880 MiB，展开后占用更多空间。
3. 选择 Apple Vision Pro 模拟器并运行；真机运行需在 Signing & Capabilities 选择自己的开发团队。
4. 首页用「打开影片」选择本地文件、从相册导入视频，或添加 HTTP(S) 视频链接。影片会进入片库，自动选择播放引擎。
5. 点击影片直接观看；返回片库后可继续上次进度。长按影片可收藏、重命名、重新定位或移除记录，不删除原影片。
6. 播放页的「画面」调整 2D / AI 立体、左右 / 上下格式和左右眼；「字幕与音轨」选择音轨、内嵌字幕，或导入 SRT / WebVTT。
7. 「影院」选择现实或暗色环境，进入后可调整屏幕宽度、距离、高度，随时返回窗口。影院复用当前播放位置。
8. 「设置 → 观看历史 → 清除观看历史」会在确认后清除最近观看时间和所有续播进度，保留影片、收藏、相册副本及影片设置。清除后首页不再显示「继续观看」，再次打开影片从头播放；新的观看会重新记录进度。
8. 原有测试按钮移至 Debug 构建的「设置 → 诊断与测试」，不再占据日常界面。测试片不会写入用户影片的画面偏好。

当前最低部署版本为 visionOS 2.0。开发和编译使用 Xcode 27 / visionOS 27 SDK；旧版本运行兼容性尚未验证。

已在 visionOS 27.0.1 的实体 Vision Pro 上完成签名安装，并通过初始四条内置播放路径及连续切换的自动检查。用户确认 2D 可以观看，并在换用三球景深片后分别确认原生 SBS MP4 和 VLC SBS MKV 都有前后层次；新版 VLC 自动复测也通过。具体证据及复现限制见 `Docs/VALIDATION.md`。

另外已将官方 Big Buck Bunny 立体版制作成一分钟 Full SBS 片段并传入真机：原生 MP4 与 VLC MKV 自动检查通过，用户观看后确认立体感和声音正常。

新增六组 H.265 / Half SBS 真机自动检查也全部通过：H.265 2D MP4/MKV，以及 H.264、H.265 各自的 Half SBS MP4/MKV，均完成启动、跳转、暂停和继续检查，Half SBS 另验证帧更新与实际 16:9 显示比例。用户已确认两组 2D 画面和声音正常，四组 Half SBS 的立体感、比例和声音正常，且无闪烁、竖纹或明显卡顿。本轮范围为 30 秒、1080p SDR、HEVC Main 8-bit，不能扩展为所有 H.265 文件兼容。

也可执行：

```sh
./Scripts/build.sh
```

## 已实现

- 片库：最近打开、继续观看、缩略图、搜索、收藏、本地文件书签、网络来源的保存和编辑。
- 每部影片分别保存播放进度、2D / SBS 格式、AI 开关、立体强度和出屏程度、左右眼交换以及外置字幕文件和时间偏移。
- 统一的窗口播放器：播放/暂停、前后 10 秒、进度拖动、控件自动隐藏、重播、重试、返回片库；原生 2D 使用嵌入式 AVPlayerLayer。
- 默认自动选择引擎：MKV / AVI 等先用 VLCKit，其余先用原生。原生明确报告失败时切到 VLC 一次；仍失败则显示错误，不循环重试。普通缓冲不触发回退。
- 音轨选择、普通 2D 的内嵌字幕选择、SRT / WebVTT 导入和时间偏移。原生文本字幕和外置文本字幕由统一字幕层显示；VLC 自定义纹理路径（SBS、AI、影院）目前使用外置文本字幕，内嵌字幕暂不启用，避免错误裁切。
- Full / Half SBS（左右）及 Full / Half OU（上下）两条引擎路径共用 RealityKit 每眼材质；保留屏幕与背景的物理间隔，避免闪烁。
- 空间影院：现实 / 暗色环境、屏幕宽度 1.5–5 米、距离 2–6 米、高度 1–2.2 米；退出回到窗口，后台暂停。
- 实验性普通 2D 转 3D：Depth Anything V2 Small 在本机估计深度，Metal 合成每眼画面；默认关闭、强度默认 35%，SBS 不重复转换。

网络来源目前指 HTTP(S) 直链和引擎可播放的流地址，不包含独立的 SMB / WebDAV 服务器浏览器。内嵌字幕不覆盖所有图片字幕格式，音轨选择不会在重开影片后持久保存。空间影院和 AI 立体属于 SDR 自定义纹理路径。

产品改版已安装真机：23 项片库与播放流程自动检查通过，基础播放、引擎回退和 AI 立体回归通过。用户已确认片库续播、画面切换、影院屏幕调整与返回、字幕和音轨切换均正常，详见验证记录。

## 实验性 2D 转 3D

打开普通 2D 影片，在「画面」中选择「AI 立体」。「立体强度」控制前后层次，「出屏程度」主要展开屏幕前的中近景，同时让远景保留在屏幕后；映射连续且保持深度顺序，高档位仍保留前景内部层次。默认强度 35%、出屏 0%（平衡位置，不代表所有景物都在屏幕后）。强度为 0 时两眼显示相同画面。可固定强度 35%，对比出屏 0% / 60%；暂停时也可调节，按影片保存。影院里通过「立体效果」调整，支持恢复默认。测试菜单的「2D 转 3D · 原生 / VLC」使用 `BBB-HEVC-2D-30s.mp4/.mkv`，只取原片左眼作为普通 2D 输入，由模型重新合成立体视图，没有使用片源的另一眼。

「比例保护」默认开启，窗口的「画面」与影院的「立体效果」均可切换，暂停时即时对比，并按影片保存。它约束合成中的局部横向伸缩和纵向错位，尽量保留原片里脸部、四肢及其他物体的形状，不会按标准人体比例重塑人物；代价是部分局部景深会收敛。关闭后使用 `0.5OK` 的位移映射。旧片库中没有该设置的影片默认开启，诊断测试不覆盖影片偏好。

模型输入 518×392，深度输出为半精度单通道。视频纹理最长边限制为 1920，保持原始宽高比。Core ML 每次只计算一帧、不排队，视频刷新独立运行；播放中深度超过 150 ms 即暂用平面画面，跳转和检测到镜头切换会清空旧深度。深度做范围与时间平滑，并使用保留边界的空间滤波。Metal 使用前后景分别限幅的非线性视差映射，随出屏程度调整零视差深度并扩大中近景范围，先约束局部视差梯度，再用连续网格正向投影到两眼，避免深度边缘折叠出细碎亮暗条纹；局部压缩区增加覆盖取样，画面四边逐渐降低位移。此路径不生成遮挡后隐藏内容，深度突变附近会压缩部分层次并可能拉伸背景，换取连续轮廓。总视差上限随实际屏幕宽度收紧；影院还结合配置距离限幅，不使用眼距测量或头部追踪。左右眼显示纹理生成多级分辨率，用于窗口缩小和斜视时的预滤波，最高分辨率画面保持不变。音频仍由当前播放引擎负责。帧率显示为最近约一秒的转换提交速率，不是头显刷新率。

开发版可在「画面 → 实验对比」（影院为「立体效果 → 实验对比」）选择「稳定版 0.6.3」或「边缘与细节 · 实验」。两者保留运动对齐、可靠性控制与比例保护；新版额外参考当前原片的颜色轮廓，减少可见边缘的前后景深度混合，缺少可靠依据时沿用旧深度。此选择只在本次会话生效，暂停时也能对比，不覆盖影片参数。它不识别人类标准比例，不生成被挡住的背景，也不保证恢复细发和透明物体。第二轮本地 GPU 回归与原生/VLC 新旧四组真机短测通过，提交速率约 30 fps。用户确认新版边缘改善、人物比例自然，两条路径流畅、声音同步且无新增异常；结论限于已观看场景，本轮未做长测。

这是 SDR 实验路径，不会把片源改写成空间视频文件，也不是苹果空间照片的私有算法。单目深度不是真实测量；透明物体、头发、快速运动和遮挡边缘可能出现错误、拉伸或晃动。当前没有生成式补洞。本轮实验增加低分辨率双向运动匹配，将深度对齐到当前画面；可靠性不足的局部会减弱视差，减少遮挡和误匹配造成的形变。运动搜索范围有限，不能保证快速运动与遮挡都能恢复正确深度。HDR、4K/60fps、长时间发热以及佩戴舒适度尚需单独验证。1080p/30fps 真机短时提交速率、实际出屏效果及边缘质量的验收范围与证据见 `Docs/VALIDATION.md`，提交速率不等于头显刷新率。

## 专注观影

默认开启，可在「设置 → 观看 → 专注观影」关闭。播放时无操作 3 秒后收起标题、工具栏和播放控制，并收起窗口玻璃背景；字幕保留。轻点影片（影院中注视影片后捏合选中）恢复控制。暂停、播放结束、缓冲、错误、拖动进度或展开设置时保持可见，操作结束重新计时。单纯注视不会显示控制。隐藏只改变可见性，不移除布局，影片尺寸和位置保持稳定。

窗口通过 plain 样式配合显式玻璃背景显示片库与操作界面；NavigationStack 只包裹片库，播放页放在独立透明容器中，避免导航容器留下整块玻璃底板。专注时请求系统隐藏持久覆盖控件，系统控制条的最终呈现以 visionOS 为准。影院影片实体具有间接输入碰撞区域，控制隐藏后仍可点选影片恢复。原生空间视频也使用同样的点选入口。

开发者可运行 `python3 Scripts/generate_stereo_reference.py` 生成自制 Full SBS 对照片，并放入 App Documents 的 `StereoReference.mp4`，再通过「设置 → 诊断与测试 → 播放出屏对照（无 AI）」检查。左眼应只看到 LEFT EYE、右眼只看到 RIGHT EYE；金色圆盘在白框前、白色圆盘与白框同平面、青色圆盘在后。该对照不使用深度模型，必须在头显中判断，单张截图不能验证双眼显示。

## 立体播放控制

窗口播放原片 3D、AI 立体或原生空间视频时，进度条与播放按钮位于画面下方的独立控制栏，影片区域按实际显示比例适配，避免大块黑色容器边框。字幕与播放提示位于画面前方，屏幕仍保留防止深度冲突的 5 mm 间距。普通 2D 与立体播放共用上述专注观影行为。

影院控制面板随屏幕宽度、距离和高度移动，面板上沿与屏幕底边留出间隔；展开屏幕调整时也会重新测量面板。影片画面不裁切，片源本身编码的黑边仍保留。

## 相册视频与原生空间视频

首页「打开影片 → 从相册导入」使用系统 PhotosPicker，只读取你选中的视频，不请求整个相册的读写权限。选择当前编码，以文件方式接收，不把整段视频加载进内存，也不主动转码。iCloud 资源由系统下载，导入期间显示进度并支持取消。

选中的文件先暂存，再移入 App 自有片库；这是占用本地空间的独立副本，关闭或更新 App 后仍可续播。移除相册影片时会确认删除 App 内的副本，原相册视频不受影响。普通本地文件仍只移除记录。取消或失败的临时文件自动清理。

空间视频检测依据视频轨的 `containsStereoMultiviewVideo` 特征，不根据扩展名猜测。检测到后使用 `VideoPlayerComponent(avPlayer:)` 并请求 `.stereo`，保留原生左右眼；默认固定立体屏幕，支持现有影院尺寸和距离控制。显示「空间视频 · 原生 3D」，无需手动选择 SBS / OU，也不提供重复的 AI 转换。原生空间解码出错时显示错误，不静默切成 VLC 单眼画面。

参考：[Apple PhotosPicker 文件导入](https://developer.apple.com/documentation/photokit/bringing-photos-picker-to-your-swiftui-app)、[Apple RealityKit 立体视频](https://developer.apple.com/documentation/realitykit/rendering-stereoscopic-video-with-realitykit)。

## 上下 3D（Over-Under / Top-Bottom）

在「画面 → 影片格式」选择「上下 3D · 全高」或「上下 3D · 半高」。全高如 1920×2160，每眼 1920×1080；半高如 1920×1080，每眼存储 1920×540，显示时恢复高度。默认上半幅为左眼，下半幅为右眼；眼序相反时打开「交换左右眼」。设置按影片保存，窗口和影院共用。

新导入且文件名包含 `full-ou`、`fullou`、`full-tab` 或 `_stereo_abl` 的影片默认全高上下；`half-ou`、`halfou`、`half-tab` 默认半高上下。其他命名仍需手动选择，不仅凭宽高猜测；已有片库记录保留原设置，需要手动切换一次。

## SBS 的边界

这是真正的每眼纹理选择：每帧从拼接视频提取左、右半幅，通过 Shader Graph 的 Camera Index Switch 分别送到左右眼，不是把拼接画面放大成普通屏幕。模拟器的单眼画面不能证明立体感，必须真机检查。

当前 SBS 为 **SDR 验证路径**：

- 原生：AVPlayerItemVideoOutput 请求 BGRA 帧，Core Image 转换至两张线性 RGBA16Float GPU 纹理，通过 LowLevelTexture 更新。
- VLC：明确使用软件解码，输出 BGRA，最长边限制为 1920；内存中只保留最新待显示帧。音频由 VLC 自身播放和计时。
- GPU 最多保留一组提交中的立体帧，慢时丢帧，不积压视频帧。
- Full SBS 的显示宽高比是输入宽高比的一半；Half SBS 使用输入宽高比。支持常规方形像素、水平编码的 SBS；旋转元数据、非方形像素暂未处理。
- 尚未实现 HDR / Dolby Vision 保真、蓝光 MVC、180° / 360°。VLC SBS 内嵌字幕未做每眼重新排版，当前须使用外置文本字幕。
- 自定义纹理路径不是 `VideoPlayerComponent(avPlayer:)`；后者不能直接接收这个 VLC 播放器。

本地 MP4 / MOV 中的 MV-HEVC 空间视频会自动识别，交给 Apple VideoPlayerComponent 原生双眼播放，窗口和影院共用；不走单眼 BGRA 提取或 AI 转换。实际验收状态见验证记录。

HTTP 地址可能受 Apple 网络安全策略限制，优先使用 HTTPS；本项目没有全局关闭系统网络安全限制。

## 源码结构

- `App/`：应用入口、窗口和配置。
- `Playback/PlayerModel.swift`：播放会话、切换、生命周期与状态。
- `Playback/PlaybackOptions.swift`：引擎路由和立体布局。
- `Bridge/VPPVLCSession.m`：官方 VLCKit 内的 libVLC 4 接口封装、异步停止、帧缓冲。
- `Rendering/StereoRenderer.swift`：同一时间戳的两眼裁切、GPU 上传和 RealityKit 渲染。
- `Rendering/DepthEstimator.swift` / `DepthStereo.metal` / `StereoReprojector.swift`：Core ML 深度计算、单任务调度、深度平滑及双眼合成。
- `Resources/StereoMaterial.usda`：每眼材质。
- `Library/MediaLibrary.swift`：影片记录、文件访问书签、缩略图和持久化。
- `Playback/PlayerExperience.swift` / `Subtitles.swift`：续播、每片设置、音轨和文本字幕。
- `Views/`：片库、播放页、画面与字幕面板、设置和空间影院。

上述目录均在 `VisionProPlayer/` 下。

## 依赖与复现

依赖固定到 VideoLAN 官方仓库提交 `2e0868f5ed40fe59cd92f377645fdcc260c6e759`，包引用 2026-09-29 的 VLCKit 4 开发版二进制；由 Swift Package Manager 验证 SHA-256。

- 官方仓库：https://github.com/videolan/vlckit
- 不要直接切换到 master；libVLC 4 的 C API 仍会变化。

- Debug 构建支持 `--smoke 2d|mkv|sbs-native|sbs-vlc|lifecycle|routing|product|depth-native|depth-vlc` 开发验证参数；Release 不执行此逻辑。
